## 1. ОБЩЕЕ ОПИСАНИЕ СИСТЕМЫ

### 1.1 Назначение
Система представляет собой **Telegram Mini App** для демонстрации объектов недвижимости (новостроек) с полной административной панелью управления.

### 1.2 Целевая аудитория
- **Агенты по недвижимости** — владельцы системы
- **Клиенты агентов** — пользователи каталога (покупатели квартир)

### 1.3 Основные компоненты
1. **Клиентское приложение** (Mini App в Telegram)
2. **Административная панель** (веб-интерфейс)
3. **Бэкенд** (Google Apps Script)
4. **База данных** (Google Sheets)
5. **Хранилище файлов** (Google Drive)

## 3. КЛИЕНТСКОЕ ПРИЛОЖЕНИЕ

### 3.1 Описание
Telegram Mini App, которое открывается внутри Telegram. Предназначено для просмотра каталога объектов и отправки заявок.

### 3.2 Основной функционал

#### 3.2.1 Приветственный экран
- Логотип и название компании
- Фоновое изображение
- Кнопка "НАЧАТЬ ПОДБОР"
- Настраивается через `client-config.json` (branding section)

#### 3.2.2 Каталог объектов
**Список объектов:**
- Карточка объекта: фото, название, адрес, цена, район, метро
- Статус: "Активен" / "Скрыт"
- Фильтры:
  - 💰 Цена (до 5/10/20/50/100 млн ₽)
  - 📍 Районы (чекбоксы)
  - 🚇 Метро (чекбоксы)
  - 🚪 Комнаты (чекбоксы)

**Просмотр объекта:**
- Галерея фото (карусель)
- Основная информация: цена, адрес, метро, класс, отделка, срок сдачи
- Описание
- Преимущества (список)
- Планировки (фото или текст)
- Кнопка "Заказать консультацию"

**Карта:**
- Отображение объектов на карте (Leaflet.js)
- Маркеры с ценой
- Клик по маркеру → открытие объекта

#### 3.2.3 Форма заявки
Поля:
- Имя (обязательно)
- Телефон (маска +7)
- Telegram (необязательно, латиницей)

**Отправка:**
- Данные сохраняются в лист `Leads`
- Отправляется уведомление в Telegram боту-почтальону
- Статус по умолчанию: "new" (Новая)

#### 3.2.4 Меню
- 🏠 Каталог
- 👤 Обо мне (динамическая страница)
- 📞 Контакты (данные агента из `AgentData`)
- ⚙️ Админ-панель (только для владельца)

## 5. СВЯЗЬ АДМИНКИ С КЛИЕНТСКИМ ПРИЛОЖЕНИЕМ

### 5.1 Общая конфигурация

**Файл:** `client-config.json`

```json
{
  "client": {
    "projectId": "demo-miniapp-realty",
    "scriptUrl": "https://script.google.com/.../exec",
    "secretKey": "Secret_new_int_111"
  },
  "sheets": {
    "agentData": "https://docs.google.com/.../pub?gid=...&output=csv",
    "pages": "https://docs.google.com/.../pub?gid=...&output=csv"
  }
}
```

### 5.2 Общие источники данных

| Данные | Источник | Где используется |
|--------|----------|------------------|
| **Объекты** | Google Apps Script (`Listings`) | Клиент: каталог<br>Админка: CRUD |
| **Заявки** | Google Apps Script (`Leads`) | Клиент: создание<br>Админка: просмотр, статусы |
| **Профиль** | Google Apps Script (`AgentData`) | Клиент: контакты<br>Админка: редактирование |
| **Страницы** | Google Apps Script (`Pages`) | Клиент: "Обо мне"<br>Админка: редактирование |

### 5.3 Синхронизация данных

#### 5.3.1 Объекты
**Создание/Обновление (Админка):**
1. Admin → `apiCall('create'/'update', params)`
2. Apps Script → валидация PIN
3. Запись в `Listings`
4. Ответ: `{success: true, id: '...'}`

**Чтение (Клиент):**
1. Client → `fetch(scriptUrl)`
2. Apps Script → чтение `Listings`
3. Фильтрация: только `active=TRUE`
4. Ответ: массив объектов

**Синхронизация:**
- Мгновенная (через Google Sheets)
- Клиент кэширует данные при загрузке
- Админка обновляет список после сохранения

#### 5.3.2 Заявки
**Создание (Клиент):**
1. Client → `fetch(scriptUrl, {action: 'save_lead', data: {...}})`
2. Apps Script → запись в `Leads`
3. Отправка уведомления в Telegram
4. Ответ: `{success: true, id: 'lead-...'}`

**Чтение (Админка):**
1. Admin → `apiCall('get_leads', {})`
2. Apps Script → валидация PIN
3. Чтение `Leads`
4. Ответ: массив заявок

**Обновление статуса (Админка):**
1. Admin → `apiCall('update_lead_status', {id, status})`
2. Apps Script → валидация PIN
3. Обновление поля `status` в `Leads`
4. Ответ: `{success: true}`

#### 5.3.3 Фото
**Загрузка (Админка):**
1. Выбор файла → Base64
2. `apiCall('upload_image', {image, fileName})`
3. Apps Script → декодирование Base64
4. Создание Blob → сохранение в Drive
5. Установка доступа: "Anyone with link can view"
6. Получение URL: `https://lh3.googleusercontent.com/d/FILE_ID`
7. `apiCall('get_last_file_url')` → получение URL
8. Сохранение URL в объекте/профиле

**Отображение (Клиент и Админка):**
- Прямая загрузка с Google Drive CDN
-Fallback на placeholder при ошибке

### 5.4 PIN-защита

**Генерация хеша:**
```javascript
function hashPin(pin) {
  var rawHash = Utilities.computeDigest(
    Utilities.DigestAlgorithm.SHA_256,
    pin
  );
  return rawHash.map(function(byte) {
    var v = (byte < 0) ? 256 + byte : byte;
    return ('0' + v.toString(16)).slice(-2);
  }).join('');
}
```

**Проверка:**
1. Admin отправляет `pin` в каждом запросе
2. Apps Script вычисляет хеш полученного PIN
3. Сравнение с `Config!B1`
4. Если не совпадает → ошибка "Неверный PIN"

**Защищённые операции:**
- ✅ `create`, `update`, `delete` (объекты)
- ✅ `get_leads`, `update_lead_status`
- ✅ `get_agent_profile`, `update_agent_profile`
- ✅ `get_pages`, `update_page`

**Открытые операции:**
- ✅ `save_lead` (заявка от клиента)
- ✅ Чтение объектов (без скрытых)

1. Открыть Apps Script

function checkRateLimit(ip) {
  var key = 'rate_' + ip;
  var count = cache.get(key);
 
  if (!count) {
    cache.put(key, '1', 3600); // 1 запрос в час
    return true;
  }
 
  if (parseInt(count) > 10) {
    return false; // Слишком много запросов
  }
 
  cache.put(key, String(parseInt(count) + 1), 3600);
  return true;
}

## 3. СВЯЗКА КЛИЕНТСКОГО ПРИЛОЖЕНИЯ И АДМИНКИ

### 3.1 Механизм взаимодействия

**Клиентское приложение и админка — это два интерфейса, работающих в рамках одного Telegram Mini App:**

1. **Клиентская часть** (`index.html`) — это публичный каталог, который видят все пользователи
2. **Админ-панель** (`admin.html`) — открывается в iframe поверх клиентской части при нажатии на кнопку меню "Админка"

### 3.2 Передача данных между частями

**Через URL-параметр (для Telegram initData):**

```javascript
// index.html передает initData в iframe
function openAdminPanel() {
  const initData = encodeURIComponent(window.Telegram.WebApp.initData);
  iframe.src = 'admin.html?v=1.1.1&tg=' + initData;
}

// admin.html получает initData из URL
(function() {
  var params = new URLSearchParams(window.location.search);
  var tgParam = params.get('tg');
  if (tgParam) {
    sessionStorage.setItem('tg_initData', decodeURIComponent(tgParam));
  }
})();
```

**Через sessionStorage (для PIN и авторизации):**

```javascript
// После успешного ввода PIN
sessionStorage.setItem('adminAuth', 'true');
sessionStorage.setItem('adminPin', input);

// При каждом запросе к API
var payload = {
  action: action,
  initData: sessionStorage.getItem('tg_initData'),
  pin: sessionStorage.getItem('adminPin')
};
```

## 4. МЕХАНИЗМ АВТОРИЗАЦИИ И БЕЗОПАСНОСТИ

### 4.1 Два способа авторизации

| Способ | Где работает | Как работает |
|--------|--------------|--------------|
| **Telegram initData** | В Telegram (телефон) | Криптографическая подпись HMAC-SHA256 |
| **PIN-код** | На ПК (браузер) | Проверка через сервер (не в конфиге!) |

### 4.2 Авторизация через Telegram (основная)

**Процесс:**
1. Telegram передает `initData` приложению
2. `initData` содержит данные пользователя + подпись
3. Подпись создана с использованием токена бота
4. Сервер проверяет подпись тем же токеном
5. Если подпись верна и `user.id` совпадает с `TELEGRAM_CHAT_ID` — доступ разрешен

**Код проверки (`Code.gs`):**
```javascript
function isValidTelegramInitData(initData, expectedUserId) {
  var botToken = PropertiesService.getScriptProperties().getProperty('TELEGRAM_BOT_TOKEN');
  var data = parseTelegramInitData(initData);
 
  // Проверка подписи HMAC-SHA256
  var secretKey = Utilities.computeHmacSha256Digest('WebAppData', botToken);
  var computedHash = Utilities.computeHmacSha256Digest(dataCheckString, secretKey);
 
  return computedHashHex.toLowerCase() === data.hash.toLowerCase();
}
```

**Безопасность:**
- ✅ Невозможно подделать без токена бота
- ✅ Привязка к конкретному Telegram аккаунту
- ✅ Срок действия 24 часа

### 4.3 Авторизация через PIN (резервная)

**Процесс:**
1. Пользователь открывает `admin.html` на ПК
2. Видит экран ввода PIN
3. Вводит PIN (например, `2026`)
4. PIN отправляется на сервер (`action: 'verify_pin'`)
5. Сервер сверяет с `PropertiesService.ADMIN_PIN`
6. При успехе — возвращает `success: true`
7. Клиент сохраняет PIN в `sessionStorage`
8. PIN передается в каждом последующем запросе

**Код проверки (`admin.html`):**
```javascript
function checkPin() {
  fetch(config.scriptUrl, {
    method: 'POST',
    body: JSON.stringify({ action: 'verify_pin', pin: input })
  })
  .then(function(data) {
    if (data.success) {
      sessionStorage.setItem('adminPin', input); // Сохраняем
      sessionStorage.setItem('adminAuth', 'true');
      showApp();
    }
  });
}
```

**Безопасность:**
- ✅ PIN **не хранится** в публичном `client-config.json`
- ✅ PIN хранится только в **закрытом** `PropertiesService` на сервере
- ✅ PIN передается по HTTPS
- ✅ PIN сохраняется в `sessionStorage` (исчезает при закрытии вкладки)

### 4.4 Защита данных агента

**Изоляция:**
- Каждый агент разворачивает свою копию на **своих аккаунтах**
- У каждого агента свои:
  - Google Таблица
  - Google Apps Script
  - GitHub репозиторий

- **Нет пересечения данных** между агентами

**Публичные vs Приватные данные:**

|--------|--------------|-----------|
| `client-config.json` | GitHub (публично) | Все (но нет секретов!) |

## 5. ДВУХБОТОВАЯ СИСТЕМА УВЕДОМЛЕНИЙ

### 5.1 Зачем два бота?

**Проблема:**
- Для проверки `initData` нужен токен **бота-приложения** (того, через которое открывается Mini App)
- Для отправки уведомлений лучше использовать **отдельного бота** (чтобы не смешивать логику)

**Решение:**
- **Бот-приложение** (`TELEGRAM_BOT_TOKEN`) — только для проверки подписи `initData`
- **Бот-почтальон** (`TELEGRAM_NOTIFICATION_BOT_TOKEN`) — только для отправки уведомлений

### 5.2 Настройка переменных

В **Script Properties** должно быть **три переменные**:

```
TELEGRAM_BOT_TOKEN = 123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11 (токен бота-приложения)
TELEGRAM_NOTIFICATION_BOT_TOKEN = 789012:GHI-JKL3456mnoPQR-stu89VWX (токен бота-почтальона)
TELEGRAM_CHAT_ID = 2038206387 (твой личный Telegram ID)
ADMIN_PIN = 2026
```

### 5.3 Процесс отправки уведомления

**Когда:** При сохранении заявки (`saveLead`)

**Код (`Code.gs`):**
```javascript
function sendTelegramNotification(data) {
  // Используем токен БОТА-ПОЧТАЛЬОНА
  var token = PropertiesService.getScriptProperties()
    .getProperty('TELEGRAM_NOTIFICATION_BOT_TOKEN');
  var chatId = PropertiesService.getScriptProperties()
    .getProperty('TELEGRAM_CHAT_ID');
 
  var message = '🔔 Новая заявка!\n\n';
  message += '🏢 Объект: ' + data.objectName + '\n';
  message += '👤 Имя: ' + data.clientName + '\n';
  message += '📞 Телефон: ' + data.clientPhone + '\n';
 
  UrlFetchApp.fetch('https://api.telegram.org/bot' + token + '/sendMessage', {
    method: 'post',
    payload: JSON.stringify({ chat_id: chatId, text: message })
  });
}
```

**Результат:**
- Уведомление приходит от **бота-почтальона**
- В личный Telegram агента (`TELEGRAM_CHAT_ID`)
- С данными о заявке

## 1. БИЗНЕС-МОДЕЛЬ И СТРАТЕГИЯ

### 1.1 Гибридная модель монетизации
Продукт поддерживает два режима работы одновременно, переключение между которыми осуществляется изменением статуса в админке:

| Режим | Описание | Управление доступом |
| :--- | :--- | :--- |
| **Аренда (Subscription)** | Ежемесячная оплата | Поле `expires_at`. При истечении → статус `suspended` |
| **Продажа (Lifetime)** | Разовая оплата, бессрочный доступ | `plan_type = lifetime`, `expires_at = 2099-12-31` |

### 1.2 Отказ от коробочной модели
- ❌ Агент **НЕ получает** исходный код
- ❌ Агент **НЕ имеет** доступа к Apps Script или репозиторию
- ✅ Агент получает только **ссылку** на приложение и **PIN-код**
- ✅ Весь код, инфраструктура и данные находятся под полным контролем владельца платформы

### 1.3 Единая платформа (KISS)
- Один приватный репозиторий на GitHub Pages
- Один проект Google Apps Script
- Изоляция агентов осуществляется через `agent_id` на уровне бэкенда
- Никаких дополнительных площадок (Cloudflare, Supabase и т.д.) на текущем этапе

### 5.1 Принцип нулевого доверия
Каждый запрос к бэкенду проходит проверку:
1.  `checkAgentAccess(agent_id, telegram_user_id)`
2.  Совпадение `telegram_user_id` с записью в листе `Agents`
3.  Проверка `status === active`
4.  Проверка `expires_at > now()` (для subscription)
5.  Только после этого — выполнение действия с фильтрацией по `agent_id`

### 5.2 Защита от горизонтальной эскалации
- Невозможно получить данные другого агента, подставив чужой `agent_id`
- `telegram_user_id` жёстко привязан к `agent_id` в таблице
- Даже при знании чужого `agent_id` доступ будет отклонён

- `initData` — данные Telegram (если есть)
- `pin` — PIN-код (для защищённых операций)

**Сервер проверяет:**
1. Существует ли агент с таким `agentId`
2. Активен ли статус (`status: "active"`)
3. Не истёк ли срок подписки (`expires_at`)
4. Соответствует ли `telegram_user_id` (если передан)
5. Верный ли PIN (для CRUD операций)

### Уровень 3: Изоляция данных

**Все запросы фильтруются по `agent_id`:**
```javascript
// Пример: загрузка объектов
rows.filter(function(row) {
  return String(row[agentIdIndex]).trim() === String(agentId).trim();
});
```

**Результат:** Агент видит только свои объекты, заявки, профиль

## 1. ИСТОРИЯ РАЗВИТИЯ АРХИТЕКТУРЫ И ПРИНЯТЫЕ РЕШЕНИЯ

### 1.1 Эволюция подходов

| Версия | Архитектура | Статус | Причина отказа / Перехода |
| :--- | :--- | :--- | :--- |
| **v1.0** | Коробочная (GitHub Pages + Apps Script + Google Sheets) | ❌ Отклонена | Код передаётся агенту. Нет защиты IP. Невозможно масштабировать. |
| **v1.4** | Гибридная (Единый фронтенд + Apps Script + PIN) | ❌ Отклонена | Частичная изоляция, но сохранены фундаментальные ограничения платформы. |
| **v2.0** | SaaS на Apps Script (Мультитенантность + `no-cors`) | ❌ Отклонена | **CORS-тупик.** Apps Script не добавляет заголовки CORS для внешних доменов. Работа «вслепую» через `no-cors` ненадёжна. Невозможность подключения кастомных доменов агентов. |
| **v3.0** | **SaaS на Cloudflare (Pages + Workers + Sheets API)** | ✅ **Утверждена** | Решает все проблемы предыдущих версий. Полноценный SaaS с нуля. |

### 1.2 Ключевые обоснования перехода на v3.0

#### Почему НЕ Apps Script (окончательно):
1.  **CORS:** Apps Script физически не может отдавать данные на `prostors.ru` или `agent-ivanov.ru` без ошибок браузера. Это ограничение платформы, а не баг.
2.  **Кастомные домены:** Apps Script работает только на `script.google.com`. Персональные домены агентов невозможны.
3.  **Надёжность:** Единственный способ обойти CORS — `mode: 'no-cors'`, который делает ответы нечитаемыми. Заявки уходят «вслепую», авторизация пропускает неверные PIN, загрузка фото требует `setTimeout` и глобальных переменных.
4.  **Безопасность данных:** Для работы CSV-ссылок таблицу нужно делать публичной. Это нарушает изоляцию между агентами.
5.  **URL:** Ссылки вида `script.google.com/macros/s/...` непрофессиональны и непригодны для клиентского использования.

#### Почему Cloudflare Workers + Pages:
1.  **CORS из коробки:** Полноценные заголовки `Access-Control-Allow-Origin` для любых доменов.
2.  **Кастомные домены:** Поддержка `prostors.ru` и `agent-ivanov.ru` нативно, через CNAME.
3.  **Надёжность:** Чтение ответов сервера, обработка ошибок, синхронная загрузка фото.
4.  **Безопасность:** Google Sheets полностью закрыт от публичного доступа. Доступ только через Service Account на стороне Worker.
5.  **Единая точка входа:** Один бот `@prostors_bot`, один Mini App, маршрутизация по `startapp=AGENT_ID`.
6.  **Масштабируемость:** Бесплатный тариф (100K req/day) → $5/мес (10M req/day).
7.  **Защита кода:** Бэкенд только в репозитории владельца. Агент получает только ссылку.

#### Почему Google Sheets остаётся базой данных:
1.  Данные уже структурированы и заполнены.
2.  Не требуется миграция на SQL.
3.  Бесплатно в рамках текущего объёма.
4.  Простота администрирования для нетехнического специалиста.
5.  При необходимости переход на Supabase/Postgres возможен без изменения API (меняется только модуль доступа к данным внутри Worker).

| Уведомления в Telegram | Нет переменной `TELEGRAM_NOTIFICATION_BOT_TOKEN` в Vercel; `mode: 'no-cors'` в `fetch` скрывает ошибку |
| Админка | Кнопка скрыта (`isOwner = false`), нужна авторизация через Telegram |
| `favicon.ico` | Запрос к `/favicon.ico` падает (не реализовано в `api/index.js`) |

### 📊 Технические метрики:
- Размер фронтенда: ~2.4 MB (включая изображения)
- Время ответа API: 1.4–2.2 сек (Google Sheets)
- Зависимости: `googleapis` (в `api/`), `leaflet` (опционально)
